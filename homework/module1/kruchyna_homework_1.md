# Домашнє завдання 1 — Дослідження мережі

**Виконав:** Вадим Кручина
**Дата:** 2026-10-19

> **Примітка щодо середовища.** Команди виконувались на macOS (Darwin 24.6). У macOS немає нативних `ip a` / `ip r`,
> тому використано пакет `iproute2mac` (встановлюється через `brew install iproute2mac`), який реалізує
> Linux-синтаксис `ip` поверх системних `ifconfig` / `netstat` / `route`. Вивід за змістом відповідає Linux.
>
> **Примітка щодо приватності.** Файл публічний, тому публічні IP-адреси, MAC-адреси та link-local IPv6 замасковані як `xx`. Локальні адреси `192.168.0.x` залишено, бо це стандартний приватний діапазон, однаковий у більшості домашніх мереж.

## Завдання 1. Дослідження мережі

### Команда

```bash
ip a
```

### Результат (скорочено до активного інтерфейсу та loopback; решта — службові інтерфейси macOS у стані DOWN)

```
1: lo0: <UP,LOOPBACK,RUNNING,MULTICAST> mtu 16384 status UNKNOWN
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
    inet 127.0.0.1/8
    inet6 ::1/128
    inet6 fe80::1/64
...
6: en0: <UP,BROADCAST,SMART,RUNNING,SIMPLEX,MULTICAST> mtu 1500 status UP
    link/ether 22:62:3f:xx:xx:xx brd ff:ff:ff:ff:ff:ff
    inet6 fe80::xxxx:xxxx:xxxx:xxxx/64
    inet 192.168.0.192/24 brd 192.168.0.255
    inet6 2a02:8308:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx/64
    inet6 2a02:8308:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx/64
...
```

Додаткові команди для уточнення типу підключення та шлюзу:

```bash
networksetup -listallhardwareports   # тип інтерфейсу та апаратна MAC-адреса
ipconfig getpacket en0               # параметри, отримані від DHCP-сервера
```

```
Hardware Port: Wi-Fi
Device: en0
Ethernet Address: 88:66:5a:xx:xx:xx

yiaddr = 192.168.0.192
server_identifier (ip): 192.168.0.1
lease_time (uint32): 0xe10
subnet_mask (ip): 255.255.255.0
router (ip_mult): {192.168.0.1}
```

### Аналіз

| Параметр | Значення | Коментар |
|---|---|---|
| **Інтерфейс** | `en0` | Єдиний активний інтерфейс з IPv4-адресою (`status UP`). `lo0` — loopback, інші (`awdl0`, `utun*`, `bridge0`, `en3..en9`) — службові/віртуальні. |
| **Тип підключення** | Wi-Fi (бездротове, IEEE 802.11) | `networksetup` показує `Hardware Port: Wi-Fi` для `en0`. |
| **MAC-адреса** | `22:62:3f:xx:xx:xx` (у виводі `ip a`) | Рівень **L2 (канальний)** моделі OSI. Це «приватна» (рандомізована) Wi-Fi-адреса, яку macOS підставляє для конкретної мережі; апаратна адреса адаптера — `88:66:5a:xx:xx:xx`. Біт `2` у першому октеті (`22`) означає locally administered address. |
| **IP-адреса** | `192.168.0.192` | Рівень **L3 (мережевий)** моделі OSI. Приватна адреса з діапазону `192.168.0.0/16` (RFC 1918), видана DHCP-сервером роутера. |
| **Маска** | `/24` = `255.255.255.0` | Рівень **L3 (мережевий)**. Перші 24 біти — адреса мережі, останні 8 — адреса хоста. |
| **Gateway** | `192.168.0.1` | Домашній роутер; отримано з DHCP (`router`) і підтверджено таблицею маршрутів (`default via 192.168.0.1`). |
| **Broadcast** | `192.168.0.255` | Остання адреса мережі `192.168.0.0/24` (усі хостові біти = 1). Показано у виводі `ip a` як `brd`. |
| **Hosts** | 254 корисних адреси | 2⁸ = 256 адрес у `/24` мінус адреса мережі (`192.168.0.0`) і broadcast (`192.168.0.255`). Одну з 254 займає роутер, тож для інших пристроїв залишається 253. |

## Завдання 2. Дослідження маршрутизації

### Команда

```bash
ip r
```

### Результат

```
default via 192.168.0.1 dev en0
127.0.0.0/8 via 127.0.0.1 dev lo0
127.0.0.1/32 via 127.0.0.1 dev lo0
169.254.0.0/16 dev en0 scope link
192.168.0.0/24 dev en0 scope link
192.168.0.1/32 dev en0 scope link
192.168.0.192/32 dev en0 scope link
224.0.0.0/4 dev en0 scope link
255.255.255.255/32 dev en0 scope link
```

### Аналіз

- `default via 192.168.0.1 dev en0` — маршрут за замовчуванням: весь трафік, що не належить до локальних мереж, відправляється на роутер `192.168.0.1` через інтерфейс `en0`.
- `192.168.0.0/24 dev en0 scope link` — локальна мережа, доступна напряму (без шлюзу), на L2.
- `169.254.0.0/16` — link-local (APIPA), `224.0.0.0/4` — multicast, `127.0.0.0/8` — loopback.

**Протокол, через який отримано IP-адресу: DHCP.**

На Linux `ip r` показує це явно полем `proto dhcp` (наприклад `default via 192.168.0.1 dev wlan0 proto dhcp`).
`iproute2mac` поле `proto` не виводить, тому факт DHCP підтверджено командою `ipconfig getpacket en0`:
DHCP-сервер `192.168.0.1` (server_identifier) видав адресу `192.168.0.192` (yiaddr), маску `255.255.255.0`,
шлюз `192.168.0.1` та lease на `0xe10` = 3600 секунд (1 година). Тобто адреса динамічна, не статична.
Маршрути `scope link` (`192.168.0.0/24`, `169.254.0.0/16`) на Linux мали б `proto kernel` — їх ядро створює
автоматично при призначенні адреси інтерфейсу.

## Завдання 3. Знаходження публічної IP-адреси

### Команда

```bash
curl ifconfig.io
```

### Результат

```
2a02:8308:xxxx:xxxx:xxxx:xxxx:xxxx:xxxx
```

Сервіс повернув IPv6, оскільки провайдер надає IPv6 і `curl` обирає його за замовчуванням.
Щоб побачити публічну IPv4 (ту, що видно у світі через NAT роутера), примусово обрано IPv4:

```bash
curl -4 ifconfig.io
```

```
86.49.xxx.xxx
```

### Порівняння локальної та публічної адрес

| | Локальна | Публічна |
|---|---|---|
| IPv4 | `192.168.0.192` | `86.49.xxx.xxx` |
| Хто видав | домашній роутер (DHCP) | інтернет-провайдер |
| Де дійсна | лише в домашній мережі | у всьому інтернеті |

**Чи однакові?** Ні, різні.

**Чому?** Локальна адреса `192.168.0.192` — приватна (RFC 1918), такі адреси не маршрутизуються в інтернеті
й повторюються в мільйонах домашніх мереж. Домашній роутер має дві сторони: внутрішню (LAN, `192.168.0.1`)
та зовнішню (WAN), на якій провайдер видав публічну адресу `86.49.xxx.xxx`. Роутер виконує **NAT
(Network Address Translation)**: коли мій ноутбук відправляє пакет назовні, роутер підміняє адресу відправника
`192.168.0.192` на свою публічну, запам'ятовує відповідність у таблиці трансляцій і, отримавши відповідь,
повертає її саме моєму пристрою. Тому сервер `ifconfig.io` бачить не мою локальну адресу, а адресу роутера,
спільну для всіх пристроїв у квартирі.

**Коментар.** Різниця між адресами — нормальна і очікувана для домашньої мережі: одна публічна IPv4 на
роутері обслуговує всі пристрої за NAT, що економить дефіцитні IPv4-адреси й додатково ховає внутрішню
структуру мережі. З IPv6 картина інша: пристрій отримав глобальну адресу `2a02:8308:…/64` прямо на `en0`,
тобто для IPv6 NAT не потрібен і «локальна» та «публічна» адреси збігаються.
